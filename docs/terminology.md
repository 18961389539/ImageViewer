# 术语与本地化边界

## 统一术语

为减少菜单和对话框中的认知负担，当前文案使用以下统一术语：

- 图像：当前加载的位图数据。
- ROI：通用术语，表示区域、测量线、标注等可叠加对象。
- 绘制：创建区域或标注类 ROI。
- 测量：创建长度、角度、卡尺等测量类 ROI。
- 属性：右侧属性面板中可编辑的 ROI 参数。
- 分析：基于当前 ROI 和图像内容计算摘要、统计和导出结果。
- 当前视图：用户此刻在界面上看到的缩放、平移和叠加结果。
- 会话：一次工作状态的快照，不一定包含图像资产本体。
- 项目包：可移交的打包结果，包含会话和可选图像资产。

## 菜单分组原则

- 第一层放高频、任务导向的动作，例如打开图像、保存 ROI、适配视图。
- 第二层放低频或参数型选项，例如“分析运行”“高级性能”“伪彩策略”。
- 不把实现细节直接暴露成大量平铺菜单项，避免用户在没有明确目标时被迫理解内部机制。

## 对话框分层原则

- 默认先显示完成任务所需的最少参数。
- 只有在确实需要微调时，才展开“高级参数”。
- 警告、确认和错误提示使用统一资源文本，不在业务代码中散落硬编码字符串。

## 本地化边界

所有用户可见文案都应进入资源层：

- `ImageViewerControl/Resources/UiText.resx`
- `ImageViewerDemo/Resources/DemoText.resx`

推荐使用方式：

- XAML：通过 `UiTextExtension` 或 `DemoTextExtension` 绑定资源。
- C#：通过 `UiText.Get(...)`、`UiText.Format(...)`、`DemoText.Get(...)` 获取文本。

不推荐的方式：

- 在 `xaml` 里直接写按钮标题、菜单标题、对话框标题。
- 在控制器、服务或工作流代码中直接拼接用户可见错误消息。

## ROI 命名边界

ROI 现在区分“内部稳定类型名”和“界面展示名”：

- `RoiTypeName`：内部逻辑、序列化与分组统计使用的稳定标识。
- `DisplayTypeName` / `DisplayName`：界面展示、列表标题和属性面板使用的本地化名称。

这条边界的目标是：既不破坏文件兼容性，也允许 UI 文案继续演进。
